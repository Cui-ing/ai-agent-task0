# 第一章笔记 · AI Agent 入门

> 本章引入全书的主要概念，目的在于快速建立整体印象。

## 1.1 现代 Agent = LLM + 上下文 + 工具

**等价写法：`Agent = Model + Harness`**

### 1.1.1 LLM：Agent 的大脑（即 Model 本身）

- Large Language Model 是 Agent 的决策核心：通过预训练积累知识，拥有"理解—规划—执行"的能力。
- 一个独特能力是**内部思考**：在实际行动之前先做规划与推演，显著提升后续行动质量。

### 1.1.2 上下文：Agent 的眼睛

Agent 在每个决策点能看到的全部信息，共 5 个部分：

| 位置 | 组件 | 说明 |
|:--|:--|:--|
| 静态前缀 | System Prompt | 由开发者编写，定义身份、权限、行为准则；还可包含跨对话保存的用户记忆与动态注入的环境状态 |
| 静态前缀 | Tool Definitions | 可用工具的名称、功能描述与参数格式 |
| 动态轨迹 | User Messages | 用户输入，可包含 RAG 动态检索引入的外部知识 |
| 动态轨迹 | Assistant Messages | 模型此前的回复：思考过程 / 文本内容 / 工具调用请求 |
| 动态轨迹 | Tool Results | 工具执行后返回的结果 |

> **上下文 = 静态前缀 + 轨迹（消息历史）**，每次调用 LLM 都会把两者拼接后送入模型。

### 1.1.3 工具：Agent 的手脚

- 感知类（搜索 / 文件 / API）把环境变成观察；执行类（代码 / 命令）把决策变成行动。
- 此外还有协作工具（子 Agent / 人工确认）、事件触发工具、用户沟通工具。
- 工具调用流程：**声明工具 → 模型决定调用 → 结果追加到上下文 → 模型继续决策**。
- 设计原则：通用基础能力用于组合探索；高风险操作（支付 / 删除 / 发邮件）用专用工具 + 权限约束。

### 1.1.4 ReAct 循环

**想（Reasoning）→ 做（Acting）→ 看（Observing）**，不断重复直到任务完成。

- 轨迹只增不改，每轮都能看到全部历史。
- 退出条件：无工具调用 / 调用 final_answer / 错误超限 / 达到最大轮数。

## 实验 1-1：上下文消融实验

**实验设置**：在 `chapter1/context` 中，对同一任务分别去掉一个上下文组件，观察 Agent 表现（DeepSeek V4 Flash，3 任务 × 5 模式）。

| 模式 | 结果 | 迭代 / 工具调用 | 现象 |
|:--|:--:|:--|:--|
| `full` | ✓ 正常 | 3it / 4–6tc | 基线：先查汇率再汇总 |
| `no_history` | ✗ 无最终答案 | 10it / 30–45tc | 重复操作、丢失进度，耗尽迭代预算 |
| `no_reasoning` | ✓ 正常 | 3it / 4–6tc | 与基线几乎无差别 |
| `no_tool_calls` | ⚠ 编造数字 | 1it / 0tc | 无法调用工具，直接编汇率 |
| `no_tool_results` | ⚠ 编造数字 | 7–9it / 11–16tc | 盲目重试后仍给出无依据的答案 |

**结论**：组件并不等价。

- 工具定义与工具结果决定"能不能行动 / 有没有闭环"；缺失时不会报错，而是给出一个看起来毫无破绽的**编造答案**——"给出了回答" ≠ "完成了任务"。
- 历史记录防止重复操作。
- 思考过程只要能从上一步工具结果重建，丢了代价很低。

## 1.2 Harness 工程与 Environment

- `Agent = Model + Harness`；`Harness = 上下文管理 + 工具接口 + 约束 + 验证 + 纠正`。
- **Environment（环境）**：Agent 交互的对象——文件 / 数据库 / 网页 / 用户 / 其他 Agent，有自己的状态与转移规律。
- Harness 只负责 **Agent 边界内、模型之外** 的运行与治理，不包含环境本身（即使仿真环境与 Agent 跑在同一进程）。

五要素中，早期框架只关心前两个（"能做事"），生产级系统重心在后三个（"可靠地做事"）：

| 要素 | 要点 |
|:--|:--|
| 约束 | 默认关闭、显式开放权限（类似手机 App 权限管理） |
| 验证 | 只看结构化数据，不看模型自由生成的文本（可能被提示注入操纵） |
| 纠正 | 静默重试、熔断、回退人工 |

**编排模式**：工作流（路径代码写死，稳但不变通）vs 自主 Agent（路径动态决定，灵活但成本 / 错误风险高），实践中混合使用。原则：**先优化提示词 → 再工作流 → 最后才上自主 Agent**。

## 1.3 贯穿全书的设计模式

| 模式 | 说明 |
|:--|:--|
| 提议者—审核者 | 产出与评判分开，评判只看产物不看推理（自审不可靠） |
| 渐进式披露 | 先给目录，按需加载细节 |
| 只增不改 | 状态追加演进，可缓存 / 可重放 / 可审计 |
| 边界集 + 保留集 | 改动要同时验证"该变的"和"不该受影响的" |
| 最小 diff + 可回滚 | 每次改动尽量小、带来源、能单独回滚 |

## 1.4 小结与收获

1. 模型固定时，扩展上下文与工具（观察空间 / 动作空间）往往比换模型更有效。
2. 消融实验让我直观看到：上下文组件的重要性要靠实测，不能靠直觉。
3. 安全是架构问题：护栏分上下文层 / 执行层 / 数据层，越往下越不依赖模型自己的判断。
